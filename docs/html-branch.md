# HTML 分支：单文件微缩场景（"一歌一页"轻量版）

> 状态：研究验证阶段，未排期实现
> 日期：2026-10-18
> 来源：AI 单文件网页画廊 prompt 挖掘（html.happy-pet.fun，67 件作品）＋ 网页版模型实测

## 1. 背景

Music Universe 的 3D runtime 是重型体验：桌面浏览器、WebGL、性能预算。
HTML 分支探索另一条轻量路线：**每首歌附带一个单文件 HTML 微缩场景**——
Three.js 走 CDN、零构建、双击即运行，手机可看、可转发。

定位：不是替代 3D runtime，而是 roadmap Phase 4 "shareable experience pages"
的轻量候选格式。重型 3D 负责"哇"，轻型 HTML 负责传播。

## 2. 模式报告：高分 prompt 的规律

样本：画廊按 AI 观赏评分排序的头部 14 件（12 件 3D、2 件 2D）；站内评分严苛，
67 件中仅 3 件达到 85+。

### 2.1 五件套结构（导演式）

以 93/100 的《樱花车站微缩场景》（claude-opus-5-5）为范本：

1. **交付形态＋交互规格**：沙盒微缩、第三视角、可拖拽/旋转/缩放；显式负约束
   （"没有任何 UI 界面元素"）防模型加戏。
2. **构图约束**：正方形底座、所有元素在底座上、构图紧凑——diorama 范式。
3. **质感目标**：一句话定调（"小巧、精致、可收藏的模型感"）。
4. **风格词**：行话而非虚词（"三渲二""日式二次元动画氛围"）。
5. **材质光影**：干净、轮廓明确、色彩有层次。

### 2.2 双范式：信息密度＞长度

反直觉发现：prompt 长度与 AI 评分脱钩——1500 字长 prompt 得 93 分，
19 字（"创建一个html内容是svg绘制一个鹈鹕骑自行车的2d动画"）得 86 分，
2 字＋参考图（"复刻画面"）得 73 分。

- **范式 A「导演式」**：信息全放在 prompt 里，模型只负责执行。适合强指令跟随
  模型，上限最高，可控、可自动化、模型可替换。
- **范式 B「极简式」**：prompt 只给方向，靠顶级模型审美补完。上限高但不可控、
  贵、换模型即换风格。

管线选型结论：选 A。World Bible 本身就是详细信息，天然适合信息前置；
且"模型只是执行器"意味着以后哪个便宜用哪个，不被单一模型绑架
（与本仓库 adapter 思想一致）。

### 2.3 可验收性

站内 AI 评分维度＝构图、材质、光影、色彩——prompt 的每个要求都应是可打分项。
写"好看"没用，写"轮廓明确、色彩有白昼阳光的层次感"有用。

### 2.4 气质词＞风格词

"安静、治愈、带一点午后慵懒"这类情绪词，比风格词更能定调。模板中气质词槽位
优先级高于风格词。

### 2.5 动效清单

把"生命力"拆成可执行条目（如：时钟秒针走动、信号灯变色、鸟落电线），
而非"加入生动的动效"一句带过。

### 2.6 负约束写法

"否定＋肯定"组合拳："不要人物，但候车室内部一定要有足够内容"；
交付约束："单个 HTML 文件、无外链字体、无加载界面、无第三方统计代码"。

### 2.7 建模语言＞意象语言（实测补遗）

"七个'窍'的抽象象征物"这类意象语言 → 模型自由发挥 → 结果稀疏；
"直径 3.5 个单位的球体，表面顶点噪声起伏，半透明琥珀色（transmission 0.85）"
这类建模语言（名词带数量＋材质＋尺寸＋位置）→ 结果结实。
World Bible→prompt 的编译规则：形容词换数字，意象换零件清单。

## 3. 模板 v2（变量版）

### 模板 A：导演式（主力）

```text
请制作一个单文件 HTML 微缩三维场景（Three.js 走 CDN importmap，零构建，
双击即运行），主题：{WorldBible.核心意象}，{写实/三渲二/低多边形}质感。

【交付形态】沙盒式微缩场景，第三视角；鼠标拖拽旋转、滚轮缩放；
无任何 UI 元素{{或：仅保留一个极简圆形播放键＋小音符按钮（选择本地音频）}}。

【构图约束】完整的正方形底座，边长 {N} 个单位；{WorldBible.空间布局}；
构图紧凑、层次清晰，呈现小巧精致、可收藏的模型感。

【主体】{WorldBible.核心意象建模描述：每个名词带数量＋材质＋尺寸＋位置}。

【环境】{WorldBible.环境元素}；{背景处理：弧形背景板/渐变天空}；
不要人物（除非 WorldBible 明确要求）。

【风格气质】{WorldBible.风格词}；气质：{WorldBible.情绪词}。

【材质光影】{WorldBible.材质}；{WorldBible.光影}；轮廓明确，色彩有层次感。

【音乐联动】Web Audio API 实时分析音频并驱动场景：
低频能量 → {WorldBible.低频映射}；高频能量 → {WorldBible.高频映射}；
节拍 → {WorldBible.节拍映射}。必须包含演示模式：无音频时用合成振荡器
模拟频谱，保证双击打开即有完整动态。浏览器自动播放策略要求用户手势
启动 AudioContext，播放键即承担此职责。

【动效清单】{从 WorldBible 叙事节拍生成 5~8 个微动态条目}。

【负约束】单个 HTML 文件；无外链字体；无加载界面；无第三方统计代码；
所有逻辑内联。

【看图建模（如有概念图）】附概念图一张：按图的构图、配色、元素位置建模；
文字负责图片看不出的部分（精确尺寸、材质参数、交互、音乐联动、动效）；
两者冲突时以文字为准。背景远景收成弧形背景板，不做无限延伸。
招牌类中文文字必须用 Canvas 2D 绘制成贴图，字形正确、无错别字。
```

### 模板 B：极简式（备选，批量铺量时）

```text
{WorldBible 一句话方向}。单文件 HTML，Three.js 微缩场景，可拖拽旋转缩放，
无 UI。{附：风格参考图}
```

## 4. 实验记录（2026-10-18）

| # | 输入 | 模型/方式 | 结果 |
|---|------|-----------|------|
| 1 | 画廊 3D prompt（樱花车站类） | DeepSeek 网页版 | "雨夜便利店"：34KB 单文件，Three.js CDN，零构建可运行，质量高 |
| 2 | 自写幻想题 prompt（混沌 v1，意象语言） | DeepSeek 网页版 | 可运行但稀疏；结论见 2.7 |
| 3 | 混沌 v2（建模语言重写）＋真实音乐 | DeepSeek 网页版 | OK；Web Audio 驱动验证通过（低频→呼吸、高频→发光、节拍→波纹） |
| 4 | 骑楼 prompt：纯文字 vs 附概念图 | DeepSeek 网页版 | 附图后思考变短、输出降质（网页版图片通道疑为灰度内测模型）；纯文字版稳定 |
| 5 | 骑楼 prompt 纯文字 | ChatGPT 网页版 | 更精致光滑，但丢失骑楼拱券等标志性特征——精致≠准确 |

核心结论：
- 现实题材有 ground truth 可比对验证，幻想题材没有——测试设计优先现实题材。
- 音乐联动（Web Audio AnalyserNode＋演示模式振荡器）是模板独创部分，已验证可行。
- DeepSeek 网页版走纯文字路线；图片→代码链路待多模态 API 验证，不阻塞当前。
- GPT-image 概念图路径暂缓：概念图仅作人工 art direction，不进模型。

## 5. 管线 v1（已定，2026-10-18）

```text
World Bible
  → 详细 prompt（模板 A 导演式，信息前置）
  → DeepSeek（纯文字，网页版/API）
  → 单文件 HTML（Three.js CDN，Web Audio 音乐联动）
```

- 批量生产时需配套"生成→运行验证→修复"验收闭环（agentic render-verify-revise）。
- 进入 Phase 4 排期前不做实现；本分支不改变现有 runtime 与 schema。

## 6. 在产品中的位置
