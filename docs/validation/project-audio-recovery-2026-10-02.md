# 项目歌曲关联与恢复修复验收

> 日期：2026-10-02
> 结论：两个歌曲阻塞已修复，A4 工程验收通过。
> 对应前次验收：[完整创作流程](creator-workflow-acceptance-2026-10-02.md)

## 目标与范围

修复 Phase 2 创作流程的两个阻塞项：作品记录正在使用的歌曲；刷新、打开和导入后能选回匹配歌曲。最小流程为上传 → 编辑 → 保存/导出 → 刷新/导入 → 选回原文件 → 预览、跳转、结束与重播。

外部资产、依赖、音频云存储、发布和 AI 服务均未增加。继续保留既有工作树改动。

## 实现结果

- 音频成功读取后，项目记录文件名、真实时长、字节数与 SHA-256 指纹。新上传歌曲使用用户提供、权利未核实的私人预览记录。
- 刷新、打开及导入时显示所需歌曲，提供选回原文件和替换歌曲的入口。内容、大小和时长匹配后恢复播放；相同内容改名可以恢复，同名不同内容会被拒绝。
- 音频字节留在本机。JSON 保存歌曲识别信息；用户须保留原音频文件。旧项目缺少指纹时，需要明确替换歌曲。
- 替换歌曲先读取候选文件，成功后同时提交播放器与项目信息。失败保留原歌曲和作品；切换项目会停止播放并取消待加载文件。
- 场景编辑撤销保持歌曲关联。清理音频先终止浏览器读取，再释放文件链接，避免残留请求报错。

## 性能、可访问性与权利

生产主应用包为 97.20 kB / gzip 27.70 kB；修复前为 92.14 kB / gzip 26.10 kB。生成资产仍为 16 个，共 6.07 MiB。指纹计算读取一个文件；较大文件的峰值内存与低端设备耗时尚需专项测量。

恢复入口为带标签的文件输入，焦点会突出选歌按钮；小窗口展开音量设置时播放器可滚动。错误使用可读提示，原文件错误可以重新选择。既有键盘焦点、800×600 布局和减少效果检查继续纳入回归。浏览器使用独立临时档案、硬件渲染和生产构建资源；资源通过测试拦截器提供，未测真实网络冷加载预算。

文件识别信息属于本地项目数据。权利未核实标记限制为私人预览用途，后续公开发布仍需权利审核。工程回归通过后，Phase 2 的人类创作者观察和目标设备校准继续保留。
